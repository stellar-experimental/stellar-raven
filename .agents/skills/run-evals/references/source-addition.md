# Source-addition lanes

A new service, index, corpus, or source namespace changes evidence access and routing competition
at once. Before a paid A/B for one, add these to the pre-spend lines and have them reviewed.

1. **Fix the gainable denominator.** Count a case as upside only when its baseline is below
   Correct, a probe verified every missing key fact in the new source, and the residual is not
   answer craft. State `X of N audited-gainable` before launch.
2. **Measure the capture slice.** Every existing routing case the candidate newly captures at top 1
   enters a paired no-regression QA arm. A source can help its own questions and flood others;
   aggregate routing does not measure that.
3. **Control verdict variance.** Use two or three runs per arm on a small slice, or a second judge
   for each cross-arm grade difference before it counts. Put the rule and its cost ceiling in the
   pre-spend lines.
4. **Grade facts as well as verdicts.** Pre-register missing-fact and wrong-claim deltas as the
   mechanism metric. Correct/Partial/Wrong stays the headline.
5. **Measure provenance directly.** If unique or first-party sourcing is the value, define its own
   instrument, such as uniquely reachable golden-source URLs. QA-grade movement is not a proxy.
6. **Review labels first.** Adjudicate cases whose expected source predates the candidate namespace
   before the A/B, and pre-commit the disposition for the retrieval-win, QA-neutral, routing-cost
   outcome. Operation names feed routing, so inspect exact per-case captures.

When the candidate surface differs from HEAD, the answering server must serve the complete
candidate manifest, spec, adapters, and descriptions from one pinned revision. A partial local
overlay is not a valid arm.
