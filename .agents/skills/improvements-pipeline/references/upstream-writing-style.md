# Upstream Writing Style

Use ASD-STE100-inspired language for upstream issues, pull requests, and handoffs.

- Use active voice.
- Keep each sentence at 20 words or fewer.
- Put one idea in each sentence.
- Use simple tenses.
- Use one term for one idea.
- Do not use idioms, slang, or unnecessary jargon.
- Keep each paragraph at six sentences or fewer.
- Preserve exact paths, identifiers, names, versions, URLs, and numbers.

Use this issue structure:

1. State the affected surface and defect.
2. State the user or maintainer impact.
3. Give reproducible evidence.
4. Ask for the smallest correction.
5. Preserve the source record and resolution handoff.

Before filing, confirm each claim against current evidence. Remove internal workflow details and unsupported claims.
