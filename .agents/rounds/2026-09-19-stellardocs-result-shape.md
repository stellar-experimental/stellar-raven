# stellarDocs result shape — 2026-09-19

Status: fix implemented and gated. End-to-end check with an external harness in progress.

## Authority and scope

The user asked for the second defect from the `includeContent` round
(`2026-09-19-stellardocs-include-content.md`) to be fixed, tested, and opened as a second pull request if
it holds. This branch stacks on `fix/stellardocs-include-content`. Scope is catalog text and schemas for
the stellarDocs search operations. No adapter, scorer, instruction, or tool-description change. No paid
instrument of this repository ran, and no repository evaluation budget was spent.

## Defect

The eleven stellarDocs search operations said `Returns: Array of ... hits` and carried no `outputSchema`,
so the rendered signature ended in `data: unknown`. The adapter returns an object:
`{ hits, nbHits, nbPages, page, clientFiltered? }`. Agents wrote `r.data.map(...)` and the script failed
with `r.data.map is not a function`, which costs one `execute` call. In 1,272 logged external-harness
runs, 52 of 53 attributable errors of this kind came from stellarDocs operations. In the A/B for the
`includeContent` fix the rate rose from 3.1% to 7.2% of `execute` calls on the fixed build.
`search_docs_in_category` also named two keys that never existed (`rawNbHits`, `filteredCount`).

## Change

- `specs/stellar-docs.json`: an `outputSchema` on the eleven search operations, in the style of
  `get_doc_page_sections`. `returns` now reads `{ hits: Array of ... hits: { ... } }`. The false key names
  left `search_docs_in_category`. `snippet` is marked optional, because heading records carry none.
- `catalog/manifest.json`, `specs/super-spec.json`: regenerated by their scripts. The rendered signature
  now ends in `data: Search...Output` with `hits: { ... }[]`.
- `test/adapters.test.ts`: every stellarDocs search operation must document an object with a `hits`
  array and must not say "Returns: Array of". For each operation the adapter result is validated against
  its `outputSchema` (required keys, types, and no undocumented key), with a content record and a heading
  record. Twelve tests fail without the schemas.
- `.agents/TODO.md`: the result-shape item is removed, because this change does it.

## Routing

`returns` text is scored. I tested 17 wordings with a strict comparison against the base branch. Any new
word moves scores widely: "object", "data", "not", "page" changed up to 355 of 544 cases. The output
schemas change nothing. The final wording uses only words that the text already had, so ten operations
are identical in every case and score. The one exception is deliberate: removing the two false key names
from `search_docs_in_category` lowers that operation's score by about 10 points in 7 of 544 cases. Two
extended-lane cases (`q-pc-address-types-strkey`, `q-ti-parse-raw-ledger-data`) reorder stellarDocs
operations among themselves at ranks 2 to 4. No graded flag changes in any lane, and every accepted total
is unchanged (legacy 219/298/326 of 338; skills 17/23/23; holdout 12/26/29, 10 forbidden captures).
