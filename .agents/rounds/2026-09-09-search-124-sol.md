## Proposed smallest general repair

Add an intent-preserving step inside service diversity.
Do not change the scorer, coverage gates, field weights, exact matches, or labels.

The step applies only to already gated operation candidates.
It changes only a service's later quota slot.
It never changes the first selected candidate for that service.

Use these rules:

1. Run the existing gated scorer unchanged.
2. Run the existing service-diversity selection unchanged.
3. Inspect gated overflow operations for each service at its quota.
4. Ignore schema-derived `keywords` when checking intent.
5. Require at least four distinct query content tokens.
6. Require the description plus one positive `x-routing` phrase to cover every content token.
7. Require that phrase to match at least two content tokens.
8. Require that phrase to add one token missing from the description.
9. Exclude a `detail` retrieval lane.
10. Preserve the service's first selected candidate.
11. Replace at most one later same-service slot.
12. Replace only a selected candidate with weaker intent coverage.
13. Choose the qualifying overflow candidate with the highest existing score.
14. Restore existing score order with the existing id tie-break.

This rule uses source structure, not a query list.
It uses no operation identifier or special vocabulary.
It also preserves each service count on the page.

For both leaderboard queries, the target covers all content tokens.
The accepted `top projects` phrase supplies the missing `top` token.
`scout.searchRepos` does not cover `activity` without schema keywords.
The selector therefore replaces `scout.searchRepos` with `scout.getLeaderboard`.

The target keeps its original score and gated tier.
The page keeps its total, truncation flag, and service counts.
Exact operation-id searches remain unchanged because the exact hit stays first.
