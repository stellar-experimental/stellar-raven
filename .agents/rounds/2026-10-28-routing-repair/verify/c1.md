## Findings

**S1. One sub-change has no measured effect. Remove it, or justify it with a probe.**
I split C1 into variants:

- `c1a`: scoring hunk only.
- `c1b`: scoring hunk plus `indexes.length < quota`, with the original victim ordering kept.
- `c1`: `c1b` plus the victim-ordering rewrite.

`c1b` and `c1` give **identical topHits on all 544 rows on both sources**. The rewrite drops
`intentCoverage` from the victim sort and changes `indexes.slice(1)` to `indexes.slice()`. It is
untested scope that "one mechanism per step" does not allow. It also changes behavior that no row
measures: the service's top entry can now become the victim on a score tie. Recommend: C2 keeps the
original victim ordering (`c1b` form), unless a probe shows that the rewrite is needed.

**T1. `search.test.ts:1039` is not "old behavior". It records a real invariant change.**
The test asserts that at most two Lumenloop entries appear on the controlled-vocabulary page. With
C1, the main page is: ecosystem-scout skill, `lumenloop.search_directory`, `lumenloop.get_project`
(329, newly gated), `scout.searchProjects`, and `lumenloop.get_categories` (backfill). That is
three Lumenloop entries, and `scout.getRfps` drops. The scoring hunk alone (`c1a`) already puts
three Lumenloop entries on the page, before any selector change. So the cap fails because the
removal of schema-only admission shrinks the gated pool, and the fill path then exceeds the soft
quota. The lead must decide whether the two-per-service cap is a contract. If it is, C1 breaks it. If
it is not, the test change needs a recorded reason. The other three failures are consistent with
the intended change:

- `scoring.test.ts:313` tests the schema-only rescue that C1 removes.
- `scoring.test.ts:361` compares against a keywords-only score that is now null.
- `drift-141-routing.test.ts:270` checks the page total: it changes from 6 to 5, and `truncated`
  changes from true to false, because the gated pool shrinks.

Each one still needs a rewritten assertion, and none should be deleted.

**R1. The x402 loss is the check-6 shape on a real row.** On fresh, five gated Scout entries
(266–287) hold the page. Soroban Docs (ungated 399) cannot enter, because
`TIER_INTERLEAVE_MARGIN` × 266 = 425.6. Warning for later candidates: changing the 1.6 margin to let
399 in is a tuned constant. It would need evidence on all rows and the probes, not on this row only.

**G1. Generality.** The diff contains no operation ID, service name, query string, or new constant.
It changes only `src/catalog/scoring.ts` and `src/catalog/search.ts`. No test, case, label, gate,
golden, or override file changes. The frozen-input hashes are unchanged. CONFIRMED general.
