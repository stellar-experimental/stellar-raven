## Findings

**E1. The whole-token rule is stricter than routing-token canonicalization.** `allowed` compares
`canonicalRoutingToken` forms. That function folds plurals and `-ing` forms, but not `-ed` or `-es`
verb forms. So `connected`→`connect` and `publishes`→`publish` now count as "unsupported" and lose 4–5
points. Today the effect is small: no graded row moves because of it. But it is a correctness gap in
a mechanism meant to remove only *unrelated* substrings. Recommend: define "supported" as a whole
token **or** a token that `canonicalRoutingToken` would fold on both sides. Better still, use one
shared stem function, so that the scorer and this check cannot disagree. Do not add an ad hoc suffix
list.

**E2. Duplicated vendor constants.** `schemaAugmentedScore` hard-codes the coverage bonus (`25`, `× 10`)
and the description weight (`5`). They match `vendor/search-scoring.ts` (lines 131–132) and
`UNGATED_FIELD_WEIGHTS.description` today. They are copies, though: if the vendor changes, the
subtraction drifts silently. Recommend: reference the existing constants, or add a unit test that pins
the subtraction to the vendor's bonus. These are not tuned constants, so G1 still holds.

**E3. The new losses were held up by spurious evidence.** OZ (−top3) and Friendbot (−top5, an
extended row, so the extended diagnostic regresses 117→116) both lost substring-only evidence from
stopword fragments. I classify both as **honest losses**: the removed evidence was never
legitimate. They are still losses under addendum 2 and check 10. Reverting the mechanism would
re-legitimize the `has`⊂`phase` class. The structural fix belongs in the competition (tier margin and
page composition), not in restoring the fragments. The lead decides acceptance (rule 2).

**G1. Generality.** No operation ID, service name, or query string appears. The diff changes only
`scoring.ts` and `search.ts`. No test, case, label, gate, golden, or override file changes. CONFIRMED
general, apart from E2.
